# Sendust security envelope

Authoritative sources in the sendust repository: `docs/discovery/threat-model.md`, `docs/engineering/security-strategy.md`, `docs/engineering/reliability-strategy.md`, `docs/engineering/test-harness-contract.md`, `docs/architecture/error-model.md`, and `docs/discovery/constraint-ledger.md`. These rules are requirements, not preferences.

## TLS and transport

- TLS certificate and hostname verification are mandatory. No insecure bypass flag, no plaintext fallback, no "verify=optional" mode — in MVP, ever.
- SMTP via lettre is the only MVP outbound transport; implicit TLS and STARTTLS are the supported modes. Protocol behavior lives only in `transports::smtp`.
- TLS fixtures for tests (valid, expired, self-signed, wrong-host, incomplete-chain, malformed) live under `tests/fixtures/tls/` and are generated by `scripts/generate-tls-fixtures.sh`; use them rather than inventing new certificate material.

## Redaction

Never place any of the following in logs, errors, or reports:

- Credentials (SMTP passwords, API keys, tokens).
- Message bodies or subject content.
- Attachment bytes.
- Unredacted filesystem paths.

Error messages carry taxonomy codes and stable context (see `docs/architecture/error-model.md`), not sensitive payloads.

## Resource caps and lifecycle

- Hard caps on message size, recipient count, and attachment sizes come from the architecture hard-caps decision (ADR-0009); enforce them deterministically and fail with taxonomy errors, never by truncating silently.
- One active send per transport; a second concurrent send fails immediately with BUSY. Close is explicit, idempotent, and bounded — never dependent on garbage collection.
- Attachment file reads are opt-in, capped, and follow the attachment filesystem policy (ADR-0014): read from disk only at send composition, never fetch from URLs.

## Tests and networking

- Fake SMTP/TLS tests use loopback-only networking (127.0.0.1). No test may open an external network connection.
- The test harness uses the seams and safety rules of `docs/engineering/test-harness-contract.md`; do not bypass the fake transport to reach a real network.

## Trust boundary

Sendust is an embeddable library, not an SMTP server or hosted service. It trusts the embedding application for configuration but treats the SMTP relay as untrusted for input validation purposes: normalize and validate all relay responses and server capabilities before acting on them.
